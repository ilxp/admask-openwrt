# AdMask 🛡️

> **Adversary Masking** —— 阻断威胁，净化网络，保护隐私。

**AdMask** 是一个专为 OpenWrt 路由器设计的本地透明代理与**深度流量过滤系统**。有别于传统的 DNS 去广告，AdMask 通过 **MITM（中间人解密）** 技术深入 HTTPS 腹地，不仅能拦截域名，更能**精准切除网页浮层、改写播放器 API、甚至直接删除视频流中的广告分片**。为你打造真正的全屋网络净化。

---

## 🌟 为什么选择 AdMask？（核心特色）

传统的去广告方案（如 DNS 拦截、Hosts 屏蔽）只能拦截“域名”，面对如今结合了同一域名下发的广告、服务端拼接的视频贴片，往往束手无策。**AdMask 实现了降维打击**：

*   🎯 **满血 ABP 与 uBO 生态**：原生支持 **Adblock Plus (ABP)** 网络过滤规则与 **uBlock Origin (uBO)** 全量扩展语法。内置 46 个高级 Scriptlet 引擎，支持正则、多值属性、`$remove$`、`$redirect`、`$csp` 等修饰符。**你可以无缝导入全网海量的第三方广告订阅源**，解析能力甚至超越大多数浏览器插件。
*   🎬 **流媒体广告粉碎机**：**独家的 HLS/DASH 流层过滤**，直接切除视频分片中的广告片段；支持拦截 VAST 广告协议，甚至能直接掏空播放器的 JSON API 广告数据。
*   🤝 **最佳搭档 uBO Lite**：AdMask 主攻**网络层（路由器级全屋过滤）**，建议配合浏览器端的 **uBlock Origin Lite** 插件实现页面级互补。双剑合璧，连视频网站防不胜防的“第一集服务端拼接广告”也能完美去除！
*   🚀 **双引擎性能怪兽**：默认搭载 `adblock-rust` 子进程引擎（Rust 编写，内存降低 75%，毫秒级加载）；不支持的弱鸡架构（如 mipsel）自动降级为内置 Go 引擎，零依赖平稳运行。
*   ✨ **可视化元素拾取器**：网页有漏网的广告？浏览器按下 `Ctrl+Shift+E`，鼠标点选即可生成永久拦截规则（支持防抖物理移除视频浮层）。
*   🌐 **全屋无感覆盖**：支持透明代理（客户端只需装 CA 证书）与多实例负载均衡，智能电视、IoT 设备无需任何配置即可享受净化。

## 🚀 快速上手

### 方式一：直接安装（推荐）
前往 [Releases](https://github.com/ilxp/admask-openwrt/releases) 下载对应路由器架构的安装包，通过 SSH 上传至路由器 `/tmp` 目录：

**针对 OpenWrt 24.10+ (APK 包管理器)**：
```bash
apk add ./luci-app-admask_*.apk ./admask_*.apk
```

**针对 OpenWrt 23.05 及更早版本 (OPKG 包管理器)**：
```bash
opkg install ./luci-app-admask_*.ipk ./admask_*.ipk
```

### 方式二：从源码编译
如果你使用 OpenWrt SDK 或完整的 OpenWrt 源码树，可以直接通过源码编译：
1. 将本仓库克隆到 OpenWrt 的 `package` 目录下：
   ```bash
   cd openwrt
   git clone https://github.com/ilxp/admask-openwrt.git package/admask-openwrt
   ```
2. 运行 `make menuconfig`，选中 `Network -> admask` 与 `LuCI -> Applications -> luci-app-admask`。
3. 编译：`make package/admask/compile V=s`。
4. 编译完成后，在 `bin/packages/` 目录下找到生成的安装包进行安装。

### 2. 启动与配置
1. 浏览器进入路由器后台，菜单进入 **服务 -> AdMask -> 概览**。
2. 点击 **【启动】** 按钮（启动后会自动设为开机自启）。
3. 进入 **基本设置**，勾选“透明代理”（推荐），并建议开启“阻断 QUIC 协议”（防止浏览器绕过代理）。
4. 保存并应用。

## 📜 如何安装规则源

AdMask 依赖 ABP 规则库进行拦截。由于其**完美兼容 ABP/uBO 语法生态**，你可以直接在 Github 或各大论坛寻找现成的订阅源导入。自带规则默认为空，需要手动订阅：
1. 进入 AdMask 界面 -> **规则订阅**。
2. 点击 **添加**，填入名称与订阅 URL。
   *   *Anti-AD 反诈/黄赌毒核心黑产库：* `https://cdn.jsdelivr.net/gh/privacy-protection-tools/anti-AD@master/anti-ad-easylist.txt` 
   *   *AdGuard 中文过滤列表：* `https://filters.adtidy.org/extension/ublock/filters/224.txt`
3. 更新间隔保持默认 `24h`，点击 **保存并应用**。
4. 回到概览页，点击 **重启**，等待几秒钟待规则下载并加载完毕。

## 🔐 如何安装 CA 证书（必做，这是解密过滤的前提）

要过滤 HTTPS 流量，AdMask 需要解密数据。**所有受保护的设备必须安装并信任该证书**。

**下载证书**：在 AdMask 概览页点击 **【下载 CA 证书】** (`ca.crt`)。

*   **Windows**：双击 `ca.crt` -> 安装证书 -> 本地计算机 -> 将所有证书放入下列存储 -> **受信任的根证书颁发机构**。
*   **macOS / iOS**：发送至设备安装描述文件。**iOS 安装后必须去“设置 -> 通用 -> 关于本机 -> 证书信任设置”中手动开启完全信任**。
*   **Android**：设置 -> 安全 -> 加密与凭据 -> 安装 CA 证书。

## 🛡️ 核心架构：与“翻墙代理”的配合顺序（必看）

如果你在路由器上同时运行了**翻墙代理软件**（如 OpenClash、PassWall、ShellClash 等），请务必理清流量走向。**两者的顺序极其重要，配错会导致断网或死循环**。

强烈建议使用 **AdMask 在前，翻墙代理在后** 的架构：
**流量走向**：客户端 -> **AdMask（解密并过滤）** -> **翻墙代理（出海）** -> 目标网站。

*   **原理**：AdMask 监听 80/443 端口，对拦截的国内站点直接处理；对需要翻墙的域名，AdMask 解密过滤后，作为普通的 HTTP 请求**转发给翻墙代理的本地混合端口**（如 Clash 的 `7890`）。
*   **优点**：**全屋（含智能电视）**的流量都能享受广告过滤和元素隐藏。翻墙代理只需负责转发，不再处理广告。
*   **如何设置**：
    1. 关闭翻墙代理的 TPROXY/透明代理重定向功能。
    2. 开启翻墙代理的本地 Socks5/HTTP 混合端口（假设为 `7890`）。
    3. 在 AdMask 的启动参数中，配置上游代理：
       ```bash
       admask -transparent -upstream-proxy http://127.0.0.1:7890 ...
       ```

> **❌ 绝对不要**：让 AdMask 和翻墙代理同时盲目开启全局透明代理（TPROXY 抢占 80/443），这会导致流量互相覆盖、TLS 握手无限重试或死循环。

## 🎯 进阶玩法与常见问题 (FAQ)

**Q：某些网站第一集有广告，其他集没有，或者页面角落还有零星的顽固广告？**
A：**AdMask 管“网络层”（路由器），搭配浏览器的 uBlock Origin Lite 插件管“页面层”，才是最完美的组合。**
部分网站的“第一集前贴片”是服务端拼接（广告与正片合并为一个视频文件），或者是由播放器内部的页面 JS 动态生成的。这种物理上不可分割的广告，任何 MITM 网关都无法直接切断。但你只需在浏览器安装 **uBlock Origin Lite**（uBO Lite）插件，AdMask 负责全屋网络拦截，uBO Lite 负责处理页面的 JS 探测，两者互补，即可实现 100% 的无死角净化。

**Q：视频网站加载很慢，或者无法播放（错误码 0502）？**
A：某些网站带有反广告检测或 CDN 证书锁定（Pinning）。请在 LuCI 界面进入 **服务 -> AdMask -> CDN 直通**，确保这些网站的域名在白名单中（默认已开启加速直通），这样能保留原生 HTTP/3 且防止报错。

**Q：我想在网页上精准屏蔽一个顽固浮层，但订阅里没有？**
A：在网页端使用 AdMask 提供的 **元素拾取器**。在启动参数里加上 `-picker`（或通过 UCI 开启）。然后在浏览器打开该网页，按下 `Ctrl + Shift + E`，鼠标点击你想屏蔽的广告，即可自动生成规则并永久隐藏。

**Q：为什么我的路由器（如 mipsel 架构）日志提示副引擎降级？**
A：AdMask 的副引擎由 Rust 编写（`adblock-rust`），在 `mipsel` / `mips` 架构上暂时未提供二进制包。此时系统会**自动无缝降级**为内置的 Go 引擎（urlfilter），不影响任何过滤功能，仅仅是极致性能上略有折损。如果你使用的是 `x86_64` / `arm64` / `armv7`，系统会自动启用双引擎满血模式。

**Q：有些 App 提示网络异常或连不上网？**
A：部分 App 带有 SSL Pinning（证书锁定）或检测到广告被拦截会主动断网。请将该 App 相关的核心域名或 CDN 加入 **CDN 直通白名单**，或者暂时关闭该设备的代理。

## ⚡ 性能极限与硬件建议

**MITM（中间人解密）是非常吃 CPU 算力的。** 虽然 AdMask 采用了 ECDSA 证书与 LRU 缓存优化，但仍需了解设备的性能极限，避免“小马拉大车”。

### 1. 吞吐量极限

AdMask 的处理瓶颈主要取决于：**带宽 × 平均响应体大小 × 并发数**。

| 路由器 CPU 级别 | 典型芯片 | 满血（双引擎）最高吞吐（估算） | 并发设备 | 内存占用（含 12 万条规则） |
| :--- | :--- | :--- | :--- | :--- |
| **旗舰级** | x86_64 (N5105/J4125) | **> 2.5 Gbps**（需多实例榨干多核） | 100+ 台 | ~150 MB |
| **高端级** | ARM64 (MT7981/MT6000) | **~ 800 Mbps ~ 1.2 Gbps** | 50 - 100 台 | ~120 MB |
| **中端级** | ARMv7 (MT7621A) | **~ 300 - 500 Mbps** | 20 - 50 台 | ~100 MB |
| **弱鸡级** | MIPS / 低端 ARM (128MB RAM) | **~ 100 - 150 Mbps** | < 20 台 | ~80 MB (极简规则) |

> **温馨提示**：如果你是千兆宽带，建议至少使用 `ARM64` 级别的路由器。如果是 `MIPS` 老路由器，跑满带宽时 CPU 会长期 100%，可能影响网络延迟。

### 2. 极限优化建议（榨干性能）

*   **关闭无用日志**：生产环境 **不要** 添加 `-v` 参数，并关闭规则命中日志。
*   **严控 Generic CSS**：如果路由器内存 < 128MB，请在「规则订阅」的 `max_generic_css_kb` 中填入 `1500`（或更小），防止通用隐藏规则导致内存 OOM。
*   **开启 CDN 直通**：保持默认的 `video-cdn-passthrough: true` 是保障视频加载速度的关键（跳过视频流量的解密，极大减轻 CPU 压力）。
*   **启用多实例**：对于多核 CPU（如四核 MT7981），在 UCI 中配置多实例（如监听 18080-18083），并使用 nftables 的 `numgen random` 将流量分摊到不同核心，吞吐量可直接翻倍。
*   **副引擎熔断保护**：如果遇到极限高并发，Rust 副引擎可能超时。AdMask 会连续 5 次失败后自动降级为 Go 引擎，服务永不中断，仅性能回落。

## 🗑️ 如何删除 CA 证书

如果不再使用，或之前多次重装导致残留同名证书，请按以下方法清除。

### Windows 删除方法（图形界面）
1. 按下键盘上的 `Win + R` 键，打开“运行”窗口，输入 **`certmgr.msc`** 并回车。
2. 在左侧菜单依次展开：**受信任的根证书颁发机构** -> **证书**。
3. 在右侧列表找到 `AdMask CA`，右键点击并选择**删除**（如果有多个同名，全部删除）。
*(注：CMD 用户可以执行 `certutil -user -delstore Root "AdMask CA"`)*

### macOS / iOS 删除
*   **macOS**：打开“钥匙串访问” -> 搜索 `AdMask CA` -> 右键删除。
*   **iOS**：设置 -> 通用 -> VPN与设备管理 -> 删除描述文件；并去“证书信任设置”中关闭开关。
